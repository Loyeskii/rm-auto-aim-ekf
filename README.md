# RM 装甲板自瞄：检测 + PnP + 整车状态 EKF

从一段比赛录像里估计敌方步兵的整车状态（位置、速度、朝向、自旋角速度、板到中心的距离），并把估计结果重投影回图像。

输入是一段视频和一份 IMU 姿态记录；输出是一段带四块装甲板重投影的视频、9 条状态曲线、以及逐帧的状态表。

```
视频帧 ──去畸变──> YOLOv8-pose(角点+类别) ──> solvePnP ──> 相机系位姿
                                                              │
                        IMU 姿态 ──slerp(t − 9 ms)──> R_wc ────┤
                                                              ↓
                                                    世界系量测 [x, y, z, yaw]
                                                              │
                                              EKF：预测 → 匹配 → 更新/换板/拒绝
                                                              │
                              output.mp4（红框 + 四板重投影 + 状态面板）
                              states.png（9 状态曲线 + ±3σ）
                              states.csv（逐帧状态、方差、NIS、标志位）
```

---

## 依赖

| 依赖 | 版本 | 用途 |
|---|---|---|
| OpenCV | 4.10 | DNN（ONNX 推理）、calib3d（solvePnP）、videoio、imgproc |
| CMake | ≥ 3.16 | 构建 |
| MSVC | VS2022 x64 | 编译 |

不需要 Eigen、ROS、OpenVINO。矩阵运算全部用 `cv::Mat`，配置用 OpenCV 自带的 `FileStorage` 读 YAML。

---

## 构建

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DOpenCV_DIR=C:/opencv/build
cmake --build build --config Release
```

产物：`build/Release/auto_aim.exe`。

`CMakeLists.txt` 里有两处是必须的，改动时不要删：

- **MSVC 的 `/utf-8`**：源码是 UTF-8，MSVC 默认按 GBK 读会把中文注释的尾字节当成代码，报上百条假语法错误。
- **单独拷贝 `opencv_videoio_ffmpeg*.dll`**：videoio 的后端是运行时按需加载的，不在链接依赖里。漏拷的表现是能读 avi、但写 mp4 失败。

---

## 运行

```bat
cd build\Release
auto_aim.exe --video
```

默认读 `config/config_video.yaml`（程序里默认指向它，不用带 `--config`）。可选参数：

```bat
auto_aim.exe --video --in <视频> --out <输出视频> --config <配置>
```

运行结束后 `data/processed/` 下会生成：

| 文件 | 内容 |
|---|---|
| `output.mp4` | 检测框 + 四块板重投影 + 右上角状态面板 |
| `states.png` | 9 条状态曲线，带 ±3σ 灰带 |
| `states.csv` | 逐帧 9 个状态、9 个方差、NIS、`tracking/updated/switched` |

调试用环境变量：

```bat
set RM_TRACK_DEBUG=1
```

会逐帧打印相位、正对度、马氏距离、是否更新，排查门控问题时很有用。

## 输出视频怎么看

| 颜色 | 含义 |
|---|---|
| 红框 | 检测网络 + PnP 的**实测**装甲板 |
| 黄框 `P0` | 状态里"当前正被观测"的那块板（`h(x, φ)` 正算） |
| 绿框 `P1~P3` | 由状态推算的另外三块板，图像里可能看不见 |
| 右上角 | 9 个状态量 + ±1σ + 本帧 NIS |

判读要点：**黄框应紧贴红框**（差值就是本帧新息）；**绿框应围成规矩的矩形**，和车体方向一致。黄框永远贴得住（它和车中心互为反算，正负号自相抵消），所以**只有绿框能暴露符号错误、相位搞反、半径漂移**。

## 目录结构

```
├── CMakeLists.txt
├── config/
│   ├── config_video.yaml     # 全部参数
│   └── labels.txt            # 9 类：0..5 / outpost / guard / base
├── include/                  # 11 个头文件
├── src/                      # 11 个 cpp
├── models/                   # Infantry-v8n-fp32.onnx
└── data/
    ├── original/             # 视频、IMU.txt、重投影误差.txt（内参）
    └── processed/            # 运行产物
```

模块职责：

| 模块 | 职责 |
|---|---|
| `camera` | 内参缩放（标定分辨率 → 实际分辨率）+ 去畸变 |
| `pose_detector` | ONNX 推理，输出四个角点 + 类别；角点重排、大/小判定 |
| `pnp_solver` | IPPE 解位姿 + 重投影误差 |
| `imu_reader` | 读四元数，按 `t − 9ms` 做 slerp 亚采样插值 |
| `ekf` | 9 维状态、F/H、predict/update、马氏门控 |
| `tracker` | 初始化、三道门匹配、正对度换锚、量测噪声 R |
| `reprojector` | 四块板重投影 + 状态面板 |
| `state_log` | 写 CSV、画 9 格曲线 |
| `visualizer` | 检测框与 HUD |
| `config` | YAML 读取（路径以工程根目录为基准） |

`processFrame()` 是纯函数（无跨帧状态），所有跨帧状态都在 `Tracker` 里。想脱离视频测估计器，构造一串 `Detection` 喂 `Tracker::step()` 就行。

## 配置要点

完整参数见 `config/config_video.yaml`，这里列几个改错会出大事的：

| 参数 | 值 | 说明 |
|---|---|---|
| `armor_size` | 135×55 / 230×55 mm | **灯条外角矩形**，不是模块外形（140×125），也不是整板高度（125） |
| `large_aspect` | 2.5 | 小板 2.45、大板 4.18，卡在中间 |
| `tracker.target_id` | "4" | 主目标，换车只改这里 |
| `imu.recv_latency` | 0.009 | 回退 9 ms 取姿态 |
| `ekf.sigma_px` | 1.0 | 角点噪声，R 的输入 |

关于尺寸：三种"尺寸"不能混用。网络的四个关键点落在**灯条外角**上，PnP 的物方点必须与它们同源。若把高度误填成 125（模块高度），IPPE 只能靠俯仰把高度压缩 `55/125 = 0.44` 去凑，表现是"解出的 pitch 高达 60° 以上"，同时距离整体偏大。

**自检判据**：相机近水平时，解出的 pitch 应接近 0。系统性偏离几十度，几乎一定是物方点宽高比设错了。

关于 `target_id`：本作业只跟踪一辆车，不做目标选择。真实比赛系统会给每辆车各维护一个滤波器，扩到多目标就是 `std::vector<Tracker>` 加一个选择策略，其余代码不用动。

## 数据与模型

| 文件 | 说明 |
|---|---|
| `data/original/*.avi` | 比赛录像，531 帧，1440×1080 |
| `data/original/IMU.txt` | 531 行 × 5 列：时间戳 + 四元数 `(w,x,y,z)`，24.09 Hz |
| `data/original/重投影误差.txt` | 相机内参与畸变，标定 rms 0.1448 px |
| `models/Infantry-v8n-fp32.onnx` | YOLOv8-pose，输出 4 角点 + 类别 |

模型原始权重是 fp16，OpenCV 的 DNN 无法解析（Conv 权重 fp16 + 图中有 Cast 节点），已转换为纯 fp32。若需要替换模型，保持输入 640×480、输出格式一致即可。

视频与模型体积较大，`*.avi` / `*.mp4` 已在 `.gitignore` 中排除。

**输入视频不在仓库里**（64 MB）。跑之前把 `2026-05-20_23-57-31.avi` 放到 `data/original/` 下即可，程序按 `config_video.yaml` 的 `io.video` 读取这个路径。`IMU.txt` 和 `重投影误差.txt` 体积小，随仓库一起走，不需要另外准备。

## 设计要点速查

- `dt` 取自 IMU 时间戳（0.0415 s），**不用视频 fps**：这份 AVI 是 24 fps 采集后被重标记成 30 fps 的。
- 由于相机信号与 IMU 内录的时间差，姿态按 `t − 9 ms` 做 **slerp**，不取最近行：9 ms 只占采样间隔的 0.217，取整会把修正量化掉。
- `θ` 定义为"板 → 中心"，所以 `h(x)` 用**减号**：`x_a = xc − r·cos θ`。
- 换板用**相位 φ** 表达，换锚时只改 φ、`θ` 不动，所以曲线没有 90° 台阶。
- 新息必须是**绝对**的 `wrap(量测 − (θ+φ))`；只报残差会让 `φ` 把漂移吸收掉，`θ` 会沿 90° 自由度滑走。
- 选锚看**正对度**（法线与光轴夹角最小），因为板接近相切时深度误差按 `1/cos²` 放大，整车的坐标会被带偏。
- `R` 由三部分叠加：像素传播（各向异性，深度比横向大一个量级）+ 姿态误差（主导项）+ 未建模下限。不能用一个各向同性的常数。
- 一致性用 **NIS** 验证：`νᵀ S⁻¹ ν ~ χ²(4)`，均值应接近 4，超门控比例应接近 5%。

## 已知限制

- **单目标**。视野里的另一辆车会被目标门整帧丢弃，不做联合估计。
- **外参是假设的**。题目未提供相机→IMU 外参，按"光轴与机体前向对齐、相机 x 向右 y 向下"构造固定旋转（`ImuReader::cameraToBody()`）。换成真实外参只需替换这个矩阵。
- **`r` 可观性弱**。单板观测下半径与中心位置沿径向退化，`r` 的 σ 约 0.09 m。钳位 `[0.12, 0.40]` 是退化保护，不是调参。
- **NIS 超界比例 10.2%**，高于理论 5%，说明存在少量离群量测漏过门控。
- **四块板按同一半径、同一高度建模**。真实步兵可能是前后大板、左右小板，半径不同；当前差异被 `r` 的不确定度吸收。
